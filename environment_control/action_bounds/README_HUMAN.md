## 学习目标与必要概念

在 E03 模块中，我们建立了动作定义表，理顺了策略动作数值 $a$ 怎样通过线性公式换算成电机的物理目标：
$$\text{物理目标} = \text{default\_target} + \text{scale} \times a$$

顺着这个换算流程，接下来有两个关键问题需要解决：
1. **策略动作数值 $a$ 允许取多大？** 机械关节在物理世界中都有安全活动范围（腿不能过度折叠，轮子转速也不能无限上升）。我们需要把物理世界的安全界限，反向推导为算法可以输出的动作上下界 $[L, U]$。
2. **训练刚开局时，怎样让机器人保持预期的平稳姿态？** 策略网络（Actor）初始化时，其内部均值通常处于接近 0 的状态。如果某个关节的安全范围是**非对称**的（例如腿部向上抬起的余量很大，向下压的余量很小），动作区间的几何中点就不是 0。这时如果直接令网络内部输出 0，映射出来的动作就会偏向一侧，导致机器人一开局就站不稳。

**E04 模块的核心任务，就是依据每个关节允许的物理范围反推动作边界，并通过数学公式校准出神经网络内部的初始中心偏置 $u_0$，让训练开局的确定性动作精准对应到期望的初始姿态。**

> [!IMPORTANT]
> **测试数据限制说明**：本文及测试代码中使用的单关节限位、八维软限位以及工作轮速，**全部是用于验证数学计算规则的人工测试数据**，不是 TITA 机器人的真实机械限位，也不代表经过仿真或真机验证的工作规格。

为了方便没有 Python 与高阶数学基础的读者理解，我们先直观解释几个核心术语：

| 术语 | 在本文中的含义 |
|---|---|
| **策略动作 $a$** | 决策程序交给环境的纯数字，无物理单位；列表中的每个位置称为一维，代码中按索引从 0 开始编号 |
| **物理目标** | 电机底层控制器期望达到的具体状态：角度单位是 rad（弧度），角速度单位是 rad/s（弧度每秒）。物理目标是期望值，不代表机械已经达到的实际状态 |
| **默认目标 $d$、缩放系数 $s$** | 来自 E03 的基准值 `default_target` 和放大倍数 `scale`；在未触发裁剪时，物理目标等于 $d + s \times a$。腿部的默认目标是角度，轮子的默认目标是角速度 |
| **软限位 vs 工作轮速** | **软限位**：比机械硬碰撞极限收紧一些的角度安全范围（单位 rad）；**工作轮速**：调用方指定的允许轮子旋转的速度范围（单位 rad/s）。两者描述的物理量完全不同 |
| **下界 $L$ 与上界 $U$** | 策略动作 $a$ 允许的取值区间两端，处于无量纲的动作坐标系中；代码中分别保存为 `lower` 和 `upper` |
| **区间中心 $b$ 与半宽 $c$** | 区间的几何中点 $b = (U + L) / 2$，区间跨度的一半 $c = (U - L) / 2$；代码中保存为 `center` 和 `half_width` |
| **双曲正切函数 $\tanh$** | 一种平滑的数学压缩曲线。它把任意实数平滑压缩在 $(-1, 1)$ 开区间内；输入 0 时得到 0，输入越大的正数越靠近 1，输入越小的负数越靠近 -1 |
| **反双曲正切函数 $\text{atanh}$** | $\tanh$ 的逆运算：已知压缩后的数值，反推压缩前的输入数值。输入必须严格在 $(-1, 1)$ 之间，才能解出有限实数 |
| **内部值 $u$ 与内部初始中心 $u_0$** | $u$ 是神经网络在通过 $\tanh$ 压缩前的内部原始数值；$u_0$ 是希望在训练开局使用的内部偏置。请注意：内部值 $u_0$ 与动作区间中点 $b$ 是两个不同的概念 |
| **确定性动作 vs 随机采样** | **确定性动作**：直接把内部均值代入公式计算出来的固定动作；**随机采样**：在内部均值附近加入高斯噪声扰动后再映射。由于函数非线性，固定输入的输出值不等于随机采样输出的数学平均值 |
| **Actor 与 SAC 算法** | **Actor**：根据观测产生动作的策略神经网络；**SAC**：后续计划接入的 Soft Actor-Critic（软演员—评论家算法）。E04 负责提供边界与初始化参数，不实现网络更新或训练逻辑 |

## 职责与原 PPO 的关系

在原版 PPO 配置中，各动作项都带有 `[-100, 100]` 的裁剪设置。在 E03 中我们已经说明，这只是物理目标换算完成后的宽泛安全网（单位是 rad 或 rad/s）。它不是这里要推导的有界策略动作区间。
后续接入的 SAC 算法需要策略网络输出一个有界动作分布，因此 E04 需要接收明确的物理工作范围，再结合各维度的默认基准值与 scale，将其反向换算回策略动作坐标系。

根据算法设计与 `bounds.py` 文件头的来源说明，开源 SAC 参考实现（如 `rsl_rl_sac`）通常使用关节位置限位和一个全局缩放参数来推导动作边界。本项目针对 TITA 机器人的物理特性进行了三处针对性适配：
1. **保留限位差值的正负号，不取绝对值**：如果默认姿态不慎超出了软限位（例如默认角为 0.8 rad，而限位是 $[0.9, 1.3]$），取绝对值会算出看似正常的 $[0.4, 2.0]$，把越界错误掩盖过去。保留正负号能使代码通过检查 $L < 0 < U$ 准确拦截此类错误。
2. **每维独立使用 scale，腿部与轮速分开处理**：腿部 scale 为 0.25，轮子 scale 为 5.0。轮子不能误套腿部的 0.25，也不能借用轮子的角度限位，必须从工作轮速字典独立推导。
3. **在非对称区间下显式反求内部初始中心 $u_0$**：原作者代码中网络均值层初始化为 0。当动作区间对称时，确定性动作刚好为 0；但在非对称区间下，区间几何中点 $b \neq 0$，如果直接取 $u=0$，映射出的动作就会偏离基准姿态。本项目通过 $\text{atanh}$ 显式反求出对应的 $u_0$，使初始确定性动作精准回到期望姿态。

需要强调的是：**当前 E04 的实现与单元测试仅覆盖纯数据层面的数学运算**。
代码不读取 URDF 模型文件，不从物理引擎中提取限位，也不替调用方决定工作轮速取值。**N03 Actor 与 T02 已消费本模块的边界和初始中心；E01 的真实环境接入代码也已实现，尚未在 Isaac 中运行。**

## 输入、输出与调用关系

核心函数 `derive_bounds` 接收三份输入：

| 输入参数 | 数据格式与要求 |
|---|---|
| `contract` | E03 的 `ActionContract` 动作定义表，提供关节顺序、名称、控制类型、默认目标与 scale。E04 严格按表遍历，不自行重排顺序 |
| `joint_pos_limits` | “精确关节名 → (软下限, 软上限)”字典，单位 rad，必须覆盖表中所有位置控制项（腿部关节） |
| `wheel_speed_ranges` | “精确关节名 → (最低工作轮速, 最高工作轮速)”字典，单位 rad/s，必须覆盖表中所有速度控制项（轮子关节）；不能用轮子的角度限位替代 |

函数推导并返回一个只读的数据对象 `ActionBounds`，包含五列与动作维数等长的数据：`joint_names`、`lower`、`upper`、`center`、`half_width`。无论是单关节测试的一维数据，还是完整配置的八维数据，计算逻辑均保持通用。

完成推导后，调用 `calibrate_initial_center(contract, bounds, initial_targets)` 即可计算内部初始中心 $u_0$：
- 如果省略 `initial_targets` 或传入 `None`，默认使用 E03 的默认目标（对应策略动作 $a_0 = 0$）；
- 如果显式传入自定义初始目标，每项必须是该关节对应的物理数值（角度 rad 或速度 rad/s），不能直接传入无量纲的动作数字。

整个模块的数据流与调用关系如下：

```text
E03 动作表 + 关节软限位字典 + 工作轮速范围字典
  └─ bounds.derive_bounds()
       ├─ 按控制类型分别查字典，逐维反推 L、U、b、c
       ├─ validate_bounds() 严格校验各维数值与包含关系
       └─ 返回 ActionBounds 动作边界对象
            └─ bounds.calibrate_initial_center(期望物理目标或默认目标)
                 └─ 利用 atanh 逆运算求出内部初始中心向量 u0

当前测试中的闭环往返验证路径：
  u0 → deterministic_action() 映射公式：a = b + c × tanh(u0)
     → E03 action_to_targets() 换算公式：物理目标
     → 对比是否精准回到期望的物理目标

当前下游：N03 Actor 读取 b、c 设置输出映射，并读取 u0 初始化均值头偏置；T02 Trainer 已调用，CPU 验证不代表真实开局效果
```

## 按文件、类与函数阅读代码

### `bounds.py`：推导、校验与初始中心校准

[bounds.py](bounds.py) 全部使用 Python 标准库实现。脚本开头将 E03 所在目录加入模块搜索路径 `sys.path`，复用其 [`ActionContract`](../action_contract/contract.py) 与 [`ControlType`](../action_contract/contract.py)。文件中的三个函数均为纯计算逻辑，不改动输入对象、不读写磁盘、不调用仿真引擎，也不涉及神经网络参数构建。

| 类名 | 字段与设计职责 |
|---|---|
| `ActionBoundsError` | 边界模块专用的异常类，继承自 Python 内置的 `ValueError`。推导、校验或校准遇到问题时抛出，错误信息中包含问题索引与关节名 |
| `ActionBounds` | 存储推导结果的只读数据类，包含五个等长元组字段：`joint_names`（核对顺序）、`lower`（下界 $L$）、`upper`（上界 $U$）、`center`（区间中心 $b$）、`half_width`（半宽 $c$）。数据冻结不可修改，类内不包含额外计算方法 |

| 函数名 | 输入输出与主要职责 | 关键检查与边界说明 |
|---|---|---|
| `derive_bounds(contract, joint_pos_limits, wheel_speed_ranges)` | 遍历 E03 动作表的每一行，根据控制类型从对应字典提取物理范围；要求 scale 大于 0，反推上下界并计算中心与半宽；最后调用 `validate_bounds` 并返回 `ActionBounds` | 缺少物理范围或 scale 非正时立即报错。不调用 E03 的动作表校验，也不使用 E03 的宽范围 clip 来反推 |
| `validate_bounds(contract, bounds)` | 校验边界数据的一致性：比对关节顺序、检查上下界是否为有限数、半宽是否大于 0，以及是否满足 $L < 0 < U$ | 汇总所有不合规项后一次性抛出异常；检查通过则返回 `None`，不生成新对象 |
| `calibrate_initial_center(contract, bounds, initial_targets=None)` | 接收物理目标列表（默认取 E03 默认目标），检查长度是否匹配；逐维反推策略动作 $a_0$，确认其严格落在开区间 $(L, U)$ 内，再通过 `math.atanh` 计算并返回内部中心向量 $u_0$ | 目标在端点上或越界时报错拒绝，不执行静默截断；该函数复用已有边界，内部不再重复调用推导或校验 |

### E03 `contract.py`：E04 依赖哪些接口

E04 构建在 E03 的动作定义之上，实际调用了 [contract.py](../action_contract/contract.py) 中的以下接口（其余接口可参考 [E03 人类版说明](../action_contract/README_HUMAN.md)）：

| E03 接口符号 | 在 E04 或其测试中的具体作用 |
|---|---|
| `ControlType.POSITION`、`ControlType.VELOCITY` | 区分角度控制与速度控制。E04 依据控制类型选择查软限位字典还是轮速字典；测试代码中简记为 `P` 和 `V` |
| `ActionTermSpec`、`build_action_contract(...)` | 测试程序用于构造人工动作项及默认状态，并生成单关节或测试用动作表。建表保持输入顺序，位置偏移取默认角度，速度偏移取默认速度 |
| `ActionContract.entries` 及各行 `ActionEntry` | `derive_bounds` 逐行读取 `joint_name`、`index`、`control_type`、`default_target`、`scale` 等字段开展计算 |
| `ActionContract.joint_names` | 返回有序的关节名元组。推导时保持该顺序，校验时比对顺序是否一致 |
| `ActionContract.default_targets`、`ActionContract.__len__()` | 前者提供默认物理目标列表，后者供 `len(contract)` 获取动作维数；校准函数据此提取目标并比对长度 |
| `action_to_targets(contract, action)` | 验证程序把映射后的策略动作交给该函数，换算回物理目标，检查是否精确回到期望的目标值 |
| `validate_action_contract(...)` | E03 的动作表校验器。E04 的计算函数不自动调用它；E04 的边界校验专注于边界数值本身的合理性 |

在八维测试中，代码还通过 [baseline_source.py](../action_contract/baseline_source.py) 的 `read_baseline_file` 和 `load_baseline_action_contract` 读取快照文本，生成与原版配置同结构的动作表。此过程不需要运行 Isaac Lab，仅固定使用原 PPO 快照 `8fe40aa` 中的数值；这只确定了默认目标与 scale 的来源，并未使测试中的人工限位变成真实硬件限位。

| `single_position_contract(default=0.8, scale=0.25)` | 辅助生成包含单个位置关节 `"j"` 的人工动作表，用于验证单关节数学公式，不读取 Git 快照 |

| `ARTIFICIAL_JOINT_POS_LIMITS`、`ARTIFICIAL_WHEEL_SPEED_RANGES` | 两份人工测试范围字典。字典中特意为轮子也写了角度限位，用于测试代码是否能排除干扰、准确选用轮速字典 |

## 关键计算与测试数字剖析

### 1. 从物理范围反推动作范围

E03 定义的物理目标前向公式为：
$$\text{目标} = d + s \times a$$

对其作简单的移项逆运算，即可得到对应的策略动作数值：
$$a = \frac{\text{目标} - d}{s}$$

因此，只要把物理安全范围的下限和上限分别代入逆运算，就能得出策略动作的下界 $L$ 与上界 $U$。
在 `derive_bounds` 中，代码首先根据控制类型选择查哪份字典：

```python
ranges = joint_pos_limits if e.control_type is ControlType.POSITION else wheel_speed_ranges
```

然后提取物理边界并执行反推：

```python
low, high = ranges[e.joint_name]
lower.append((float(low) - e.default_target) / e.scale)
upper.append((float(high) - e.default_target) / e.scale)
```

以测试中的单关节对称用例为例：默认角度 $d = 0.8\text{ rad}$，缩放系数 $s = 0.25$，人工设定的软限位为 $[0.3, 1.3]\text{ rad}$：
$$L = \frac{0.3 - 0.8}{0.25} = \frac{-0.5}{0.25} = -2.0$$
$$U = \frac{1.3 - 0.8}{0.25} = \frac{0.5}{0.25} = 2.0$$

算出的下界是负数 $-2.0$，代表朝小于默认角度的方向运动。
代码完整保留了这个正负符号。假设配置出现错误，默认角落在了范围之外（例如软限位是 $[0.9, 1.3]$），逆运算得出的区间将是 $[0.4, 2.0]$。这时区间两端都是正数，不包含 0。校验函数通过检查 $L < 0 < U$，能立刻发现“零动作不包含在区间内”并报错。如果计算时草率地取绝对值，就会把原本越界的配置伪装成合法的范围，造成隐患。

### 2. 为什么轮速必须单独处理

在八维测试用例中，轮速的工作范围人工设定为 $[-10, 20]\text{ rad/s}$。E03 中轮子的默认速度为 $0\text{ rad/s}$，scale 为 5.0：
$$L = \frac{-10 - 0}{5.0} = -2.0, \quad U = \frac{20 - 0}{5.0} = 4.0$$

尽管在测试的角度限位字典里，也为轮子写入了角度范围 $[-3.14, 3.14]\text{ rad}$，代码必须忽略这项数据。因为角度限位描述的是“轮子转到了哪一圈哪个朝向”，而轮子是连续旋转机构，电机底层控制的是其旋转速度（rad/s）。
此外，轮子的 scale 是 5.0，而腿部的 scale 是 0.25。如果错误地将腿部的 0.25 当作全局参数套用到轮子上，计算出的动作上界就会变成 $20 / 0.25 = 80$，与正确数值 4.0 产生整整 20 倍的偏差。

下表展示了八维人工测试用例的完整计算结果（两两对称排列，索引从 0 到 7）：

| 动作索引 | 控制对象与默认目标 | 人工物理安全范围 | scale | 动作区间 [L, U] | 中心 b | 半宽 c |
|---|---|---|---:|---|---:|---:|
| 0、4 | 腿部关节 1，0.1 rad | [-0.3, 0.7] rad | 0.25 | [-1.6, 2.4] | 0.4 | 2.0 |
| 1、5 | 腿部关节 2，0.8 rad | [0.0, 1.6] rad | 0.25 | [-3.2, 3.2] | 0.0 | 3.2 |
| 2、6 | 腿部关节 3，-1.5 rad | [-2.4, -0.6] rad | 0.25 | [-3.6, 3.6] | 0.0 | 3.6 |
| 3、7 | 轮子角速度，0.0 rad/s | [-10.0, 20.0] rad/s | 5.0 | [-2.0, 4.0] | 1.0 | 3.0 |

### 3. 中心、半宽与 tanh 各自的作用

在 `derive_bounds` 生成 `ActionBounds` 对象时，计算并保存了区间中心 $b$ 和半宽 $c$：

```python
center=tuple((u + l) / 2.0 for l, u in zip(lower, upper)),
half_width=tuple((u - l) / 2.0 for l, u in zip(lower, upper)),
```

这两个参数服务于动作输出映射公式：
$$a = b + c \times \tanh(u)$$

我们可以把这一过程拆解为三步空间变换：
1. **非线性压缩**：神经网络内部输出的原始数值 $u \in (-\infty, +\infty)$ 经 $\tanh(u)$ 压缩后，平滑映射到标准无量纲区间 $(-1, 1)$。
2. **尺度缩放**：乘以半宽 $c$，将区间缩放为 $(-c, c)$。
3. **空间平移**：加上区间中心 $b$，将区间整体平移到 $(b - c, b + c) = (L, U)$。

因为有限实数输入无法让 $\tanh$ 真正等于 $\pm 1$，所以动作映射实际对应的是**开区间 $(L, U)$**，不包含边界两个端点。

- **对称区间**（例如 $[-2, 2]$）：$b = 0, c = 2$。当内部值 $u = 0$ 时，$\tanh(0) = 0$，动作输出 $a = 0$。换算后的物理目标正好是默认姿态 $0.8\text{ rad}$。
- **非对称区间**（例如 $[-1.2, 2]$）：$b = 0.4, c = 1.6$。如果此时内部值仍然取 $u = 0$，动作输出就会变成 $a = 0.4$。换算后的物理目标变成 $0.8 + 0.25 \times 0.4 = 0.9\text{ rad}$，导致开局姿态偏离预期。

### 4. 非对称范围的初始中心校准

保持默认角 $d = 0.8\text{ rad}$、$\text{scale} = 0.25$，将物理软限位调整为非对称的 $[0.5, 1.3]\text{ rad}$：
$$L = \frac{0.5 - 0.8}{0.25} = -1.2, \quad U = \frac{1.3 - 0.8}{0.25} = 2.0$$
$$b = \frac{2.0 + (-1.2)}{2} = 0.4, \quad c = \frac{2.0 - (-1.2)}{2} = 1.6$$

如果我们希望确定性动作精准对应默认目标 0.8 rad（即 $a_0 = 0$），代入公式推导：
$$b + c \times \tanh(u_0) = a_0 \implies \tanh(u_0) = \frac{a_0 - b}{c} = \frac{0 - 0.4}{1.6} = -0.25$$

通过反双曲正切函数 $\text{atanh}$ 反求内部初始偏置：
$$u_0 = \text{atanh}(-0.25) \approx -0.255413$$

把这个 $u_0$ 重新代入映射公式：$0.4 + 1.6 \times \tanh(-0.255413) = 0.4 + 1.6 \times (-0.25) = 0$。策略动作恢复为 0，物理目标成功回到 0.8 rad。

下表总结了测试用例中涉及的四种初始设置及计算结果（近似值展示）：

| 设置情形 | 期望物理目标 (rad) | 对应策略动作 $a_0$ | 归一化值 $\frac{a_0 - b}{c}$ | 内部中心值 $u_0$ | 映射后的物理目标 (rad) |
|---|---:|---:|---:|---|---:|
| **未校准**（直接取内部零） | 默认目标 0.8 | 实际输出 0.4 | 未做反求 | $u = 0$ | 0.9（偏离） |
| **校准到默认目标** | 0.8 | 0.0 | -0.25 | $u_0 = \text{atanh}(-0.25) \approx -0.255413$ | 0.8（精准对齐） |
| **校准到指定目标** | 1.0 | 0.8 | 0.25 | $u_0 = \text{atanh}(0.25) \approx 0.255413$ | 1.0（精准对齐） |
| **校准到指定目标** | 0.6 | -0.8 | -0.75 | $u_0 = \text{atanh}(-0.75) \approx -0.972955$ | 0.6（精准对齐） |

校准函数的核心执行代码简短明了：

```python
a0 = (target - e.default_target) / e.scale
if not low < a0 < high:
    raise ActionBoundsError(
        f"索引 {e.index} ({e.joint_name}) 的初始目标 {target:g} {e.unit} 对应动作 {a0:g}，"
        f"不在开区间 ({low:g}, {high:g}) 内，tanh 映射无法精确到达"
    )
u0.append(math.atanh((a0 - b) / c))
```

代码先进行逆运算得出期望动作 $a_0$，确认其严格在开区间 $(low, high)$ 内，再通过 `math.atanh` 求解并组装成元组返回。

### 5. 为什么边界端点和越界目标会被拒绝

沿用上节的非对称算例：物理范围为 $[0.5, 1.3]\text{ rad}$，$b = 0.4$、$c = 1.6$。如果期望目标恰好设定在软限位端点 $1.3\text{ rad}$，其对应的动作数值就是上界 $U = 2.0$。代入归一化公式会得到 $(2.0 - 0.4) / 1.6 = 1.0$。
在数学上，$\text{atanh}(1)$ 趋向于无穷大（$\infty$），没有有限实数能让 $\tanh$ 严格等于 1。类似地，下端点 $0.5\text{ rad}$ 对应动作下界 $L = -1.2$，归一化后为 $(-1.2 - 0.4) / 1.6 = -1$，会导致 $\text{atanh}(-1) \to -\infty$。至于越界数值（如 1.5 rad），其归一化值大于 1，在实数范围内更是无解。

代码在此处采取严格的拒绝策略，当目标不在开区间内时立即报错中断，绝不私自做截断夹紧（clamp）后再声称精确满足条件。
同样，在推导阶段 `validate_bounds` 也会严格检查 $L < 0 < U$：因为默认姿态对应零动作，默认姿态必须严格在安全限位内部，既不能越界，也不能恰好踩在边界端点上。

### 6. 核心限制：只校准确定性动作，不保证随机采样的平均值

测试辅助函数 `deterministic_action` 的内部计算为：

```python
return [b + c * math.tanh(x) for b, c, x in zip(bounds.center, bounds.half_width, u)]
```

它直接把内部均值 $u_0$ 代入确定性公式计算，不添加任何随机噪声。**本模块所保证的“精确回到期望目标”，仅对这条确定性映射路径成立。**

在后续强化学习训练中，为了进行探索，实际采样的动作通常会加入随机高斯扰动：
$$a = b + c \times \tanh(u_0 + \sigma \times \varepsilon)$$
其中 $\sigma$ 为探索标准差，$\varepsilon$ 是服从标准正态分布的随机噪声。
由于 $\tanh$ 是非线性曲线，在非对称区间下，**对随机变量取平均再代入非线性函数，并不等于先代入非线性函数再取平均**：
$$\mathbb{E}[\tanh(u_0 + \sigma \times \varepsilon)] \neq \tanh(u_0)$$
因此，在非对称区间下，随机探索动作的数学期望值一般不会正好等于 $a_0$。
E04 不负责随机动作采样，不校准随机采样的平均值，现有单元测试也未涉及随机采样分布的评估。
