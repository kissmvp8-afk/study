## 学习目标与必要概念

在机器人强化学习中，算法学习的过程就像在查阅一台严密的“飞行黑匣子记录仪”。
每当机器人在环境中执行一次动作，系统都需要准确记录下这一刻发生的事实：

- 执行动作前，传感器看到了什么？
- 决策大脑给出了什么动作？
- 环境返回了多少即时奖励？
- 动作执行后，机器人真正到达了什么新状态？
- 这一步之后，当前轮次是否结束？是因为摔倒（真终止），还是因为时间到了（时间截断）？

如果这些记录出现混淆，比如把摔倒后的状态与下一轮刚重置的站立姿态混在一起，算法在后续学习时就会得出错误的推导。**D01 模块的核心使命，就是为“一次动作前后的事实”规定数据记录契约（`TransitionBatch`）**，明确字段、形状、来源数据的独立复制，以及后续价值开关的推导。

读完本篇说明，即使没有深度学习和 PyTorch 基础，你也能理解记录中全部 13 个字段的职责、后续价值开关为何为 `1、0、1`，以及独立复制能够保证什么、不能保证什么。

为了帮助初学者顺畅阅读，我们先以直白语言解释核心术语：

| 术语 | 通俗解释与在本文中的含义 |
|---|---|
| **经历记录（Transition）** | 强化学习中的单步转移样本，详细记录了机器人执行一次动作前后的完整事实快照 |
| **观测（Observation）与动作（Action）** | **观测**是整理后供决策或估值使用的数据，可包含机器人状态、任务指令等；**策略动作**是交给环境的 8 维无量纲数值，随后才由环境换算为电机的物理目标 |
| **奖励（Reward）与价值（Value）** | **奖励**是环境在这一步根据表现当场给出的即时分数；**价值**是网络根据后续可能获得的累计回报给出的长期预测。客观发生的即时奖励与可随训练调整的长期预测不是一回事 |
| **Actor 与 Q 网络** | **Actor（演员网络）**负责看观测并做出动作决策；**Q 网络（评论家网络）**负责评估“在某种状态下做出某个动作能带来多少长期回报”。Q 网络通常能看到一些 Actor 看不到的特权训练信息 |
| **轮次（Episode）与重置（Reset）** | 从机器人开始运行到结束（摔倒或超时）的完整过程称为一个**轮次**；结束后让机器人恢复到初始起步状态的操作称为**重置** |
| **真终止 vs 纯时间截断** | **真终止（Terminated）**：按任务规则结束本轮，如机身触地，后续价值不再接入；不要求机器人发生物理损坏。**纯时间截断（Time-out）**：只因达到时长上限而停下，仍保留重置前末状态的后续估值，不保证该状态稳定或价值为正 |
| **bootstrap mask** | “是否允许接上未来价值”的数值开关（本文简称 mask）。取值为 1 表示允许接续未来预测，取值为 0 表示未来被切断；它只控制价值计算，不代表数据是否有效 |
| **张量（Tensor）与批维（Batch Size, B）** | 张量是 PyTorch 中用来存储高维数组的基本数据容器。为了提高计算效率，系统通常把多条经历打包为一批，最外层的维度大小就是批维 $B$（表示这一批包含多少条记录） |
| **数据类型（dtype）与设备（Device）** | `float32` 是单精度浮点数，`int64` 是长整数，`bool` 是布尔真假值；设备指数据存放在 CPU 内存还是显卡 GPU 显存中 |
| **计算图（Computation Graph）与 `detach().clone()`** | 计算图是 PyTorch 记录神经网络运算过程以便反向求导的结构。保存历史经历只需要静态的数值快照，不需要旧运算图；`detach().clone()` 用于切断计算图并分配全新独立内存，防止后续数据覆盖污染记录 |
| **经验回放池（Replay Buffer）与 SAC** | 经验池用于集中存放历史经历供算法反复抽样学习；SAC 全称为 Soft Actor-Critic（软演员—评论家算法）。D01 负责定义单步记录的数据标准，不实现经验池存储或算法训练 |

## 职责与原 PPO 的差异

原版项目采用的是 PPO 算法，其数据通常只在短期内用于单次策略更新。在原版快照代码中，环境包装器 `wrapper.py` 把真终止与时间截断合并成了一个单一的 `dones` 标记；而在更新逻辑 `np3o.py` 中，程序在遇到时间截断时，会直接把当时的旧网络价值预测提前加到奖励中（`rewards += gamma * values * time_outs`）。

但对于即将接入的 SAC 算法而言，经历记录会存入经验回放池并反复读取，后续价值需要用训练时的网络重新估计；这不保证网络的每次更新都更准确。如果在采集时把旧网络预测混进奖励，训练时再加一次后续预测，就可能混入过时或重复的估值。
因此，**D01 必须严格保留最纯粹的环境即时奖励，并将真终止与纯时间截断分别独立存储**。

根据 `schema.py` 文件头与算法参考，开源 SAC 实现（如 `rsl_rl_sac`）在计算后续价值开关时采用了公式：
$$\text{bootstrap\_mask} = \text{bootstrap} + 1 - \text{dones}$$
在这个公式中，如果同一步骤既发生了摔倒终止，又恰逢时间到期，计算结果会是 $1 + 1 - 1 = 1$，从而错误地把摔倒状态当成可以继续接续未来价值的状态。
本项目确立了**“真终止优先（True Termination Priority）”**的严密规则：只要机器人摔倒了，后续价值必须果断归零。因此 D01 改为只依据 `terminated` 推导 mask，并要求上游模块传递互斥的结束标记。

> [!IMPORTANT]
> **当前实现边界说明**：D01 目前完成的是纯数据层面的张量容器封装与校验规则；代码不连接仿真引擎，不捕获真实末状态，不重置环境，也不实现经验池或训练更新。**当前 D01 与 D02～D05 已有纯数据衔接；E05 实际采集、物理仿真与 SAC 训练算法仍未接通。**

## 一次动作前后：输入、字段与数据流

### 一条完整经历涵盖的 13 个张量字段

我们把执行动作前的时刻记为 $t$，动作执行后、环境发生任何重置之前的时刻记为 $t+1$。
在 `TransitionBatch` 中，每一个字段的最外层维度都是批次大小 $B$；对于任意索引行 $i$（$0 \le i < B$），所有字段必须严格属于同一次动作，绝不能跨环境或跨时间拼凑。

| 业务含义 | 字段名称 | 形状与数据类型 | 字段保存的具体内容 |
|---|---|---|---|
| **位置与轮次索引** | `env_id` | `[B]`，`int64` | 并行环境编号（非负整数，区分不同机器人实例） |
| | `episode_id` | `[B]`，`int64` | 该环境内的轮次编号（每次重置后累加，防止跨轮拼接） |
| | `step_index` | `[B]`，`int64` | 本轮内的动作序号（非负）；D01 原样保存，不负责自增 |
| **动作前状态 (时刻 t)** | `policy_history` | `[B, 10, 33]`，`float32` | 执行动作前 Actor 看到的 10 帧历史观测（包含时刻 $t$ 本身，从旧到新排列，未经归一化） |
| | `q_observation` | `[B, C]`，`float32` | 时刻 $t$ Q 价值网络看到的特权观测（$C$ 为维数，由参数 `q_dim` 指定） |
| **实际执行的动作** | `action` | `[B, 8]`，`float32` | 实际送入环境的策略动作，处于无量纲的策略坐标系，顺序与 E03 动作表严格一致 |
| **即时收益** | `reward` | `[B, 1]`，`float32` | 本步环境返回的原始即时奖励数值，绝对不含任何未来价值补偿 |
| **动作后状态 (时刻 t+1)** | `next_policy_history` | `[B, 10, 33]`，`float32` | 动作执行后、**环境重置前**真实到达的 10 帧历史观测，依然属于本轮 |
| | `next_q_observation` | `[B, C]`，`float32` | 同一时刻 $t+1$、**环境重置前**真实到达的 Q 特权观测 |
| **轮次结束原因** | `terminated` | `[B, 1]`，`bool` | 是否发生真终止（如机身着地摔倒）；为 True 时后续价值清零 |
| | `time_out` | `[B, 1]`，`bool` | 是否发生纯时间截断（达到时长上限）；与 `terminated` 严格互斥 |
| **有效历史帧数** | `history_length` | `[B]`，`int64` | `policy_history` 中属于本轮真实经历的有效帧数（取值范围 1..10，其余为开局填充） |
| | `next_history_length` | `[B]`，`int64` | `next_policy_history` 中的有效帧数，数值必须严格等于 $\min(\text{history\_length} + 1, 10)$ |

全表共计 13 个字段。代码对类型要求极其严格（如整数必须为 `int64`，浮点数必须为 `float32`），在创建时绝不静默强转，任何类型偏差都会触发明确报错。

### 形象理解张量形状：`[B, 10, 33]`、`[B, C]` 与 `[B, 8]`

以测试中常用的参数 $B=3$（一批 3 条记录）、$C=54$ 为例：

```text
[3, 10, 33] 策略历史数据体（三维立体表格）：
第 0 层: [10 帧历史 × 每帧 33 个传感器数字]  --> 对应第 1 条经历
第 1 层: [10 帧历史 × 每帧 33 个传感器数字]  --> 对应第 2 条经历
第 2 层: [10 帧历史 × 每帧 33 个传感器数字]  --> 对应第 3 条经历
（注：10 帧里排在最后的那一帧，就是当前时刻 t 的最新观测，而不是额外拼第 11 帧）

[3, 54] Q 网络特权观测（二维平面表格）：
每一行对应一条经历，横向展开 54 个数值。维数 C 由调用方通过 q_dim 显式给出，程序绝不胡乱猜想。

[3, 8] 策略动作：
每一行对应一条经历输出的 8 个动作。它们是实际送入环境的策略动作数，尚未按 E03 换算成物理目标；不能因此断言它们未经过 Actor 内部的有界变换或区间缩放。

[3, 1] 与 [3] 的区别：
[3, 1] 是一张 3 行 1 列的细长二维表（reward、terminated、time_out 均保留此列维度）；
[3] 则是一条扁平的一维数组（env_id、episode_id、step_index 等仅需单列索引）。
```

如果当前轮次已有 3 帧真实观测，10 个历史位置中就有 3 帧有效数据，其余为开局填充；`history_length=3` 标记的是帧数，不等于已执行动作数。历史包含当前帧，D01 不生成填充或自动推断长度。

B 是记录条数，不是帧数，也不要求始终等于固定的并行环境数。E02 中平地 C=54、复杂地形 C=241 都是待运行时核对的预期；D01 要求调用方显式给出 `q_dim`，不会截断或补齐数据。

### 测试中的三条典型人工样本

在单元测试的 `artificial_data()` 中，构造了以下三条具有代表性的人工测试记录：

| 批内行号 | 环境 / 轮次 / 步数编号 | 原始奖励 | 有效历史长度变化 | 所属场景分类 | bootstrap mask 取值 |
|---|---|---:|---|---|---:|
| **行 0** | 0 / 11 / 2 | 0.5 | 3 帧 $\to$ 4 帧 | **正常运行步** | **1.0**（允许接续未来价值） |
| **行 1** | 5 / 4 / 37 | -1.0 | 10 帧 $\to$ 10 帧 | **真终止（翻车）** | **0.0**（轮次结束，截断未来价值） |
| **行 2** | 2 / 7 / 999 | 0.25 | 7 帧 $\to$ 8 帧 | **纯时间截断（超时）** | **1.0**（保留重置前末状态的估值） |

请特别留意：行号 0、1、2 只是张量批次里的存储顺序，它们分别来自不同的并行环境（环境 0、环境 5、环境 2）。**张量中相邻的两行并不代表时间上的先后连续**！后续经验池模块必须依据 `env_id`、`episode_id` 和连续的 `step_index` 来精确检索时序轨迹。

### 真实下一状态 vs 下次交互状态：两条截然不同的数据流

后续 E05 接入时，结束步应按下面的顺序处理；这不是当前已完成的仿真流程：

```text
时刻 t 决策并执行动作
        │
        ▼
物理仿真向前演进一步，产生即时奖励与结束信号
        │
        ▼
E05 在重置前捕获并保护策略历史与 Q 观测
        ├─ 本轮真实到达状态 → next_* → D01 复制、检查 → D02 经验池
        ▼
结束环境重置 → 新一轮观测 → 下一次决策
（重置后观测不能填入旧记录的 next_*）
```

在测试用例中，下一策略历史填为 `7.0`、下一 Q 观测填为 `8.0`；重置后策略历史另行构造为 `-3.0`，没有作为合法记录字段返回。
如果代码误把重置后的 `-3.0` 塞进了 `next_*`，就相当于对神经网络说：“你在快要摔倒时执行这个动作，能瞬间满血复活瞬移回站立姿态！”这会导致强化学习算法严重受挫。

## 逐文件、逐类与逐函数阅读

### `schema.py`：数据容器、安全创建、一致性校验与摘要输出

[schema.py](schema.py) 仅依赖 `torch`，不依赖图形引擎或复杂仿真环境。

| 核心组件 | 职责与设计细节 |
|---|---|
| `HISTORY_LENGTH=10`、`POLICY_OBS_DIM=33`、`ACTION_DIM=8` | 全局常量，锁定历史帧数（10 帧）、每帧策略维数（33 维）与动作维数（8 维），与根项目及 E02、E03 完全统一 |
| `TransitionSchemaError` | 专用异常类型，继承自 `ValueError`。校验不通过时抛出，错误信息中会详细列出发生问题的字段名与具体行号 |
| `TransitionBatch` | 采用 `@dataclass(frozen=True)` 声明的数据类，封装 13 个张量字段。属性 `batch_size` 直接读取 `reward.shape[0]` 返回条数 $B$ |
| `FIELD_NAMES` | 自动提取 `TransitionBatch` 全部 13 个字段名称构成的只读元组，作为参数校验的标准白名单 |

各核心函数的输入输出与安全逻辑说明：

| 函数名称 | 输入参数与返回值 | 核心逻辑与错误拦截机制 |
|---|---|---|
| `_expected_layout(q_dim)` | 输入 Q 观测维数 $C$，返回包含 13 个字段期望形状与类型的映射字典 | 内部辅助函数，例如将策略历史映射为 `((10, 33), torch.float32)`，为校验提供客观对照表 |
| `make_transition(data, q_dim)` | 输入包含 13 个张量的原始字典与参数 $q\_dim$，返回封装好的 `TransitionBatch` | **全系统核心数据复制关口**：首先比对字段名是否不多不少，检查是否均为张量；然后逐字段执行 `detach().clone()` 分配独立内存；组装对象后自动触发校验。发现缺失或多余字段立即拦截 |
| `validate_transition(batch, q_dim)` | 输入待核查的记录对象与 $q\_dim$，校验无误时正常返回 `None` | **全方位一致性检查**：逐层核对形状与类型、检查批维一致（$B \ge 1$）、检查全字段处于同一设备、检查浮点数没有 NaN 或无穷大、检查终止标记互斥、检查编号非负，以及检查有效历史长度递推合规 |
| `_shape_text(shape)`、`_rows(mask)` | 辅助函数：将元组形状格式化为 `[B,...]` 文本；将布尔掩码转换为出错的具体行号列表 | 用于拼接清晰易懂的报错定位日志 |
| `derive_bootstrap_mask(batch)` | 输入记录对象，输出形状为 `[B, 1]` 的 `float32` 张量 | 核心公式计算：`(~batch.terminated).to(torch.float32)`。真终止输出 0.0，其余输出 1.0；对通过校验的记录，与 `reward` 同设备，不修改记录 |
| `describe_transition(batch, row=0)` | 输入记录对象与指定行号，返回格式化的可读文本摘要 | 生成编号、有效历史长度、动作、奖励、结束原因、mask、形状及设备文本，自身不打印；调用 `batch_size`、`derive_bootstrap_mask`，行号越界抛 `IndexError` |

调用关系同步（审核基准 `7071e41`）：D02 直接复用本模块的内部 `_expected_layout` 分配存储，并在 append 时调用 `validate_transition`；D03 使用 `derive_bootstrap_mask`；D04/D05 读取记录字段与常量。`_expected_layout` 尚未改成公开接口；本次不改 D01 代码。

正常调用关系是 `make_transition → validate_transition → 返回记录`。直接调用 `TransitionBatch(...)` 会绕过复制与校验；`derive_bootstrap_mask`、`describe_transition` 也不自动校验整份记录。`make_transition` 会分配副本内存，保持来源设备和类型，不自动转换；校验分阶段报告问题。

形状检查的关键行为如下，`shape` 是除批维外的预期形状：

```python
if value.dim() != len(shape) + 1 or tuple(value.shape[1:]) != shape:
```

前半句检查总维数，后半句跳过最外层 B，逐项核对其余大小；例如 5 帧不能冒充 10 帧。随后另查各字段 B 一致且至少为 1、类型、设备与有限数值。结构正确不证明字段内容来自正确时刻。

## 关键代码与设计原理剖析

### 1. 复制责任为何明确放在创建入口

在强化学习工程中，仿真环境为了节省内存，往往会循环复用同一块内存缓冲区来写入最新观测。
如果我们的经历记录仅仅是用指针引用这块缓冲区，那么当下一步环境发生重置、缓冲区被刷新时，我们之前存入经验池的历史记录就会被悄悄修改覆盖，产生致命的数据污染！

为了彻底杜绝这一隐患，`make_transition` 在创建记录时明确承担了**深度内存复制**的责任：

```python
copies[name] = value.detach().clone()
```

这行简洁代码的背后蕴含着严密的两步防护：
1. **`detach()`（剥离计算图）**：经历记录保存的是过去发生过的静态客观事实。后续学习不需要沿着产生这些数据时的旧网络计算图反向传播。仅 `detach()` 仍共享原存储，不能防止来源被覆盖。
2. **`clone()`（开辟新存储）**：在内存（或显存）中开辟一块全新的独立存储区域，把数值原样拷贝过去。从此之后，外部环境缓冲区哪怕被改写成任何数值，这份记录都巍然不动。

完成复制后，函数统一组装并执行校验：

```python
batch = TransitionBatch(**copies)
validate_transition(batch, q_dim)
return batch
```

第一行把各字段副本按名称装入记录；第二行校验复制后的数据；第三行在校验成功后返回。复制不能修正来源时机：若来源在复制前已被重置覆盖，或误把重置后数据填进 `next_*`，它只会复制错误输入。E05 仍须先正确捕获末状态；D02 存储与读取已有人工 CPU 验证，实际采集循环尚未接入。

### 2. 冻结数据类为什么不等于张量内容绝对只读

在声明数据类时，代码加上了装饰器：

```python
@dataclass(frozen=True)
class TransitionBatch:
```

> [!NOTE]
> **深入理解 Python 机制**：
> `frozen=True` 锁住的是**字段的绑定关系**。也就是说，外部代码不能执行 `batch.reward = other_tensor` 这种替换操作。
> 但是，字段内部存放的是 PyTorch 张量对象。如果有人恶意调用张量的原地修改方法（例如 `batch.reward.add_(100)`），张量内部的数值依然会被篡改。
> 因此，全系统建立了双重保障：一层由 `make_transition` 负责阻断外部缓冲区的回渗，另一层由下游模块共同遵守“只读读取、绝不原地修改（In-place）张量内容”的代码契约。

### 3. 三种经历的 bootstrap mask 为什么是 1、0、1

在计算长期价值更新时，算法需要决定是否接续未来的预测价值。
`derive_bootstrap_mask` 函数的全部计算逻辑只有一行核心代码：

```python
return (~batch.terminated).to(torch.float32)
```

符号 `~` 代表布尔取反运算（True 变 False，False 变 True）。我们对照三种经典情形看其逻辑：

```text
情形 A（正常运行步）：
terminated=False, time_out=False
取反运算: ~False = True  -->  转浮点数得到: 1.0
含义：本轮未终止，允许从真实下一状态接续预估价值；不要求机器人动作平稳。

情形 B（真终止，翻车摔倒）：
terminated=True, time_out=False
取反运算: ~True = False  -->  转浮点数得到: 0.0
含义：按任务规则本轮已结束，后续价值不再接入；不要求机器人发生物理损坏，本步奖励仍保留。

情形 C（纯时间截断，超时到期）：
terminated=False, time_out=True
取反运算: ~False = True  -->  转浮点数得到: 1.0
含义：只因时间限制停下，保留重置前末状态的预估价值；不要求末状态稳定或预估价值为正。
```

#### “真终止优先”的双重保险

如果环境侧代码偶发异常，把摔倒和超时同时标记为了 True：
1. 第一道防线在 `validate_transition` 中，代码通过 `(batch.terminated & batch.time_out)` 迅速捕获冲突，报错拦截。
2. 即使有人绕过了校验函数强行推导，因为 `derive_bootstrap_mask` **只看 `terminated`**，只要 `terminated=True`，算出的结果必然依然是 0.0！
上游分类仍由 E05 负责；若它未正确标出真终止，D01 无法从观测数值自行纠正。

mask=1 不表示可以跨轮次拼接奖励。纯时间截断后，D03 仍须停止累计旧轮次奖励，只保留重置前末状态估值，不能继续加新一轮奖励。

### 4. 有效历史长度检查：能发现什么，不能证明什么

为了防止把重置后的新观测混进记录，校验函数制定了严格的长度递推防线：

```python
expected_next = torch.clamp(batch.history_length + 1, max=HISTORY_LENGTH)
bad = batch.next_history_length != expected_next
```

在同一轮次中，机器人每走一步，真实的传感器经历就会多累积 1 帧：
- 当前是 3 帧，走一步后下一时刻必然是 4 帧（`3 -> 4`）；
- 当走满 10 帧后，队列装满，由于最多只保留最近 10 帧，下一时刻依然保持为 10 帧（`10 -> 10`）。

现有测试把行 1 的重置历史和有效长度 1 一起错填进下一字段；当前长度为 10，预期下一长度仍为 10，所以检查会报错。触发错误的是长度不一致，不是观测数值为 -3.0。

> [!CAUTION]
> **理性看待校验的局限性**：
> 有效长度检查只能发现部分不一致。如果错误观测配上看似正确的长度数字，检查仍可能通过；历史满 10 帧后，重复推进也可能保持 `10→10`，不能只靠长度发现。D01 不检查历史内容是否推进一次、策略历史和 Q 观测是否来自同一物理步，也不能证明观测来自重置前。正确捕获末状态及保护快照仍由 E05 负责。

### 5. 为什么严格保持策略动作坐标与原始环境奖励

- **动作坐标严格统一**：在 E03 中我们知道，策略动作 $a$ 是无量纲的纯数字，而物理目标是换算后的真实物理量（例如轮速 $2\text{ rad/s}$）。Q 网络在强化学习中负责评价“在某状态下采取动作 $a$ 的价值”。因此，存入经验池的动作**必须永远保持与 Actor 输出一致的无量纲策略坐标**。如果经验池存的是物理值 2，而 Actor 输出的是 0.4，整个评价体系就会彻底精神分裂。
- **原始奖励坚决不加补偿**：存入经验池的奖励必须是环境纯粹的原始打分（如 0.5、-1.0）。如果按照旧 PPO 的做法提前把当时的预测价值加进去，随着网络越练越强，存入的陈旧估值就会像杂质一样污染重采样学习。价值预测必须留给训练时的最新 Q 网络现场计算。

以上是数据含义约定，不是校验器能够独立证明的事实：D01 只能核对动作形状、类型、有限数值等，不能识别动作是否已被错误换算、奖励是否已加过补偿。调用方须保证来源语义；历史保存编码前完整数据，不存会随网络参数变化的编码特征。

### 常见问题排查速查表

如果在开发或调试中遭遇报错，可对照下表快速定位：

| 报错现象与提示信息 | 优先排查方向与解决思路 |
|---|---|
| **提示缺失字段或多余字段** | 检查传入字典的键名是否与 `FIELD_NAMES` 的 13 个字段完全一致；确认没有误把重置观测 `reset_*` 或外挂的 `bootstrap` 当作字段塞入 |

| **提示终止标记与超时标记冲突** | 检查 E05 上游逻辑，真终止与超时不能同时为 True；若同时发生，必须优先归入真终止 |
| **修改了外部变量，记录数据却跟着变了** | 检查是否绕过了 `make_transition` 创建对象，或者下游代码是否违规使用了带有下划线的原地修改方法（如 `add_()`） |
| **提示有效历史长度递推不合规** | 检查 `next_history_length` 是否严格等于 $\min(\text{history\_length} + 1, 10)$；排查是否误填了重置后的长度 1，或者连续推进了多次 |
| **抽样拼接出来的经历不连续** | 切勿直接依赖张量行号相邻来判断时间先后；必须联合比对 `env_id`、`episode_id` 与连续递增的 `step_index` |
| **提示找不到 `torch` 模块** | 确认运行命令是否正确使用了包含 PyTorch 的 Python 环境 |

调试时，可随时调用 `describe_transition(batch, row)` 打印某一行记录的详细文本摘要，快速排查编号、历史长度递推与结束原因。
