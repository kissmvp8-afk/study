## 模块职责与范围

把真实交互整理成可重复学习、时间关系正确的数据，并构造多步奖励部分。

小模块保持平级，实现、测试、接口规范和人类讲解放在同一目录。维护规则统一见[根 README](../README.md#项目维护规则)。

## 边界与协作

不预测 Q，不选择控制动作，不把新一轮奖励接入上一轮。

环境与动作接口提供物理含义和真实交互；经验与回报整理这些记录；网络与学习使用记录改进策略；训练与验证负责调度并提供证据。跨模块交流使用根 README 的统一数据约定。

## 与原算法的关系

原 PPO 固定代码保存在独立的 baseline/ppo 分支。每个小模块的 README 给出原始来源和具体差异。作者的 SAC 是参考实现，TITA 的混合动作与历史编码仍需适配，不能只替换算法名称。

## 当前证据

以下为实现阶段已入库的验证记录；后续实验进展见[首页](../README.md#当前状态)。

五个小模块都有实现与 CPU 单元检查（需要 PyTorch）：D01 20 项、D02 11 项（其中 2 项为 T03 所需的保存恢复接口，`f81a92a` 新增）、D03 7 项、D04 8 项、D05 11 项，全部通过（Python 3.11.17 + torch 2.15.0，人工数据）。证据分别记录在各小模块的“实现证据与文档交接”表中。纯数据检查通过，不等于机器人仿真或 SAC 训练已经完成；整个大模块尚无训练曲线或仿真性能结果。

模块之间的实际衔接：

```text
D01 make_transition ──► D02 ReplayBuffer.append ──► sample_starts(n) / read_sequence(n)
                                                         │ SequenceBatch [M, n, ...] + valid
                                                         ▼
                                       D03 build_n_step_batch ──► NStepBatch(first, tail, R, k, γ^k, mask)
                                                         │
     D04 ObservationNormalizers（新采集的批次只更新一次；回放只 normalize）◄┤
     D05 split_windows / valid_history_mask（first.policy_history、tail.next_policy_history）◄┘
```

- 有效起点规则只有一处：D02 `valid_starts(n)`（凑满 n 条或在结束边界处停止），D03 用同一个 `SequenceBatch.valid` 再检查一次。
- D02 直接导入 D01 的内部函数 `_expected_layout` 分配存储。D01 代码未改；建议以后由 D01 正式公开该函数，届时需要同步 D01 人类版。
- 采集循环对每批新记录依次调用 D01 `make_transition`、D04 `update_from_fresh_data`、D02 `append`；训练时只调用 D04 的 normalize。
