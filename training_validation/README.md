## 边界与协作

调度模块不重新实现底层动作、回报或网络公式。

环境与动作接口提供物理含义和真实交互；经验与回报整理这些记录；网络与学习使用记录改进策略；训练与验证负责调度并提供证据。跨模块交流使用根 README 的统一数据约定。

## 与原算法的关系

原 PPO 固定代码保存在独立的 baseline/ppo 分支。每个小模块的 README 给出原始来源和具体差异。作者的 SAC 是参考实现，TITA 的混合动作与历史编码仍需适配，不能只替换算法名称。

## 给 Claude 的实施约定

1. 阅读根 CLAUDE.md、根 README、本文件、目标小模块 README 以及相关依赖契约。
2. 默认以一个小模块的可验证行为为一次工作单元；任务授权涉及多个模块时按依赖顺序分步提交。
3. 实现、验证和函数说明放在对应小模块，不把所有逻辑集中写进训练入口。
4. 修改公共输入输出时同步相关 README 和检查案例，解释改动范围；不默默更改单位、顺序、奖励和结束含义。
5. 同时维护本表与小模块状态；文档完成、代码完成、单元验证通过和仿真验证通过分别记录。

## 人怎样检查 AI 的工作

先检查模块是否完成自己声明的职责，再看输入输出是否符合契约，最后查看实际运行命令和结果。关键计算应能从逐行解释对应到验证案例。发现问题先保存最小复现记录，再修复并增加回归检查。
