## 从已有算法部件到可以追踪的实验

SAC（Soft Actor-Critic，软演员—评论家算法）的 Actor 负责提出动作，两个在线 Q 负责估计动作的未来回报，目标 Q 提供变化较慢的学习参照，温度 alpha 调节探索。前面的“网络与学习”已实现这些计算；本大模块进一步回答：何时采集、用哪批经历学习、多久更新一次、中断后恢复什么、导出后是否仍算出相同动作，以及有什么证据支持结论。

当前已连接的是 **CPU 假环境流程**。假环境有确定的人工状态更新和结束条件，能暴露时间顺序与状态传递问题；它不是 Isaac 仿真，不计算机器人接触动力学，也不能产生机器人训练成功的证据。E01/E02/E05 仍待接入。

## 数据怎样流动

```text
T01 RunConfig（来源、数值、规模、任务）
  ↓ T02 Trainer 构造模块，E03 动作表 → E04 边界/初始中心
采集：当前原始历史 → D04 归一化 → D05 窗口 → N01 特征 → N03 有界随机动作
  → 环境 step → 重置前 next_* + 下一次交互 observation 分开
  → D01 复制/校验 → D04 只统计新状态 → D02 保存原始经历
学习：D02 合法连续片段 → D03 n 步奖励/尾部 → N05 在线双 Q 更新
  → 起点采样一次 → N07 更新 alpha → N06 用新 alpha 与同次采样更新 Actor
  → N08 按频率更新目标 Q
辅助：每个学习迭代另按配置次数 D02 抽样 → D04/D05 → N02 编码器/projector 更新
  ├→ T03 检查点：学习状态 + 可选经验池；恢复后环境另开新回合
  ├→ T05：冻结 D04/N01/N03 → 确定性策略动作 → 运行端一次物理换算
  └→ T04：确定性评价记录 → 指标/报告 → 满足来源、种子、预算、阈值才可判定
T06 为这些路径组织已有检查，分别记录各层证据
```

设 E=3，每次 `step` 有 3 条经历：采集历史为 `[3,10,33]`，Q 观测 `[3,C]`，策略动作 `[3,8]`。回放批量 M=16 时，D02 读取 `[16,n,...]` 的片段，D03 输出每行实际长度 k、折扣奖励 R、γ^k 和尾记录。纯时间截断仍在重置前末状态接未来价值，真终止则不接；下一回合奖励不能混入。

D04 的统计只在采集新数据时更新，回放与推理只使用它；经验池保存原始历史，不保存会随编码器训练改变的潜特征。编码器的速度估计加隐藏特征和当前帧构成 52 维 Actor 输入；Q 使用 `[M,C]` 的训练侧信息及指定动作，不把它全部给 Actor。

## 更新频率与参数归属

默认 CPU 配置每轮采集 8 步、预热 1 轮、每学习轮 4 次 Critic 更新和 1 次辅助尝试。alpha 每次 Critic 更新都更新；Actor 按更新前计数取模，默认在第 1、3、5…次 Critic 更新后更新；目标 Q 按更新后计数取模，默认每次慢更新。辅助学习按迭代计频，不随 Critic 次数成倍增加。

| 操作 | 修改的持久状态 | 关键隔离 |
|---|---|---|
| 新数据归一化统计 | D04 policy/q 的 mean/var/count | 回放不能重复增加计数 |
| N05 | 在线双 Q、Critic 优化器 | 目标无梯度，Actor/编码器/目标 Q 不被本损失更新 |
| N07 | `log_alpha`、温度优化器 | 对同次 `log_prob` detach，不训练 Actor |
| N06 | Actor、Actor 优化器 | 用新 alpha 数值；Q 参数冻结但保留动作方向梯度；编码器隔离 |
| N08 | 目标双 Q | 参数慢更新、缓冲直接复制；tau=0 参数不变但缓冲仍复制 |
| N02 | 编码器/projector、辅助优化器与 BN 统计 | 有效历史≥6 且有效样本≥2 才更新，结束恢复 eval |

T01 的论文候选 γ=0.97、n=5、tau=0.003 与 N 模块独立入口的作者默认值不同；T02 显式传入配置使其生效。不能只看某个函数默认参数来判断本次运行用值。目标熵保留策略动作坐标下 −8 的实验约定，单位区间等价值为 `−8−Σlog(c)`；c 来自 E04 半宽。

## 恢复、导出和评价各自保证什么

T03 强制学习配置一致，只允许 name/sources/environment 这三项描述字段不同。带池 `exact_replay` 在同配置、CPU、同 PyTorch 版本下验证了下一批回放学习复现；`model_only` 实际仍恢复其他学习状态，只是池为空，需重新积累。两者均 reset 环境并递增回合号，不恢复关节、接触或随机化现场。

T05 冻结编码器、Actor 和 D04 统计。输入是一份已含当前帧的原始 `[B,10,33]` 历史，输出是策略动作，不是关节角/轮速。运行端按 E03 做一次 default+scale×a 和 clip。0.02 s/50 Hz 是接口要求，CPU 导出一致不能证明实时部署通过。

T04 的速度误差按全部步加权，稳定时长按 episode 平均，摔倒率分母包含未完成段；动作差分不跨回合。不同有效训练种子按去重计数，每组至少 3 个；交互预算要求全部记录相等，耗时预算容差 5% 是项目暂定约定而非论文结论。阈值要在正式对照前固定，当前没有真实 PPO/SAC 性能结果。

## 出现问题从哪里查

| 现象 | 先检查 |
|---|---|
| 配置无法启动 / 内存不足 | T01 未确定字段、人工标记、E/K/C 与分项预算；估算未包含整个训练和仿真占用 |
| 采集与学习计数不符 / 一直跳过 | T02 预热、更新相位、D02 合法起点、N02 有效历史 |
| 截断后目标异常 | 环境是否在 reset 前复制 next_*，D01 标记、D03 尾部、N05 mask |
| 恢复后输出或抽样改变 | T03 学习配置、D04/BN、D02 序号、生成器；环境重新采集不同是已声明边界 |
| 导出后动作不同 / 物理量差固定倍率 | T05 原始输入、冻结统计、历史是否重复、物理换算是否做了两次 |
| 报告没有性能判定 | T04 的 conclusion_blockers、信号 missing、不同训练种子、预算和阈值 |
| 检查命令通过但证据不足 | T06 选择了哪些层级、跳过/未执行数量；退出码 0 不代表仿真或性能完成 |
